# 编辑器与预览性能优化

## 背景
打开大文件（1k+ 行）和编辑大文件时，响应明显慢于小文件。
用户期望「极致性能」——大文件操作应接近小文件的流畅度。

## 目标
- [x] 优化 PieceTable 行操作：使用 `QStringView::count` / `QString::indexOf` 替代字符级循环
- [x] 实现 EditorLayout Y 缓存增量更新：仅重建从第一个 dirty 行开始的部分
- [ ] 验证性能提升：加载 10k 行文件时间 < 50ms，滚动绘制性能提升 > 2x
- [ ] 确保所有 32 个单元测试通过

## 设计

### 候选瓶颈分析

1. **EditorLayout::rebuild()** — 全行 QTextLayout 构造（O(n)），大文件开销大
2. **SyntaxHighlighter** — 全文档高亮（O(n)），可能阻塞主线程
3. **ParseScheduler** — 30ms 防抖后全量解析
