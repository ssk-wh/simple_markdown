# 文件监控与后台线程数量优化

## 背景

2026-07-30 对安装版 SimpleMarkdown 1.1.18 进行现场诊断时，进程仅打开 5 个 Tab，
但任务管理器和 WinDbg 显示约 238 个线程、14,000 个句柄。抽样线程主要停在 Qt 的
Windows 文件系统监控后端。当前 `FolderPanel::populateFolder()` 会递归遍历完整目录树，
并对每个子目录调用 `QFileSystemWatcher::addPath()`，线程和句柄数量会随目录规模增长。

此外，每个 Tab 当前固定持有编辑器搜索线程、预览搜索线程和解析线程；即使 Tab 处于
懒加载或休眠状态，`createTab()` 仍会创建这些对象。该模型在多 Tab 场景下也会造成不必要
的常驻线程。

本 Plan 记录现场问题、实施方案与验收结果。

## 目标

- 文件夹内子目录数量增加时，文件监控线程数不得线性增长。
- 懒加载、休眠和从未执行过搜索的 Tab 不应长期占用专用搜索线程。
- 为进程线程数、文件监控句柄数和启动期间主线程耗时建立可重复测量的预算。
- 保持目录树刷新、外部文件修改检测、搜索和 Markdown 解析行为正确。

## 影响范围

- `src/app/FolderPanel.cpp`、`src/app/FolderPanel.h`：目录枚举和监控策略。
- `src/app/MainWindow.cpp`、`src/app/MainWindow.h`：Tab 生命周期及单文件监控。
- `src/editor/EditorWidget.cpp`、`src/preview/PreviewWidget.cpp`：搜索任务线程所有权。
- `src/parser/ParseScheduler.cpp`：解析线程复用策略。
- Spec：补充线程数量、文件监控和资源预算不变量。
- Tests：增加大目录、多 Tab 和线程生命周期回归测试或诊断型集成测试。

- [x] 在 `specs/横切关注点/10-线程模型.md` 列出允许的工作线程、线程数量上限及懒加载 Tab 的线程生命周期。
- [x] 在 `specs/横切关注点/70-性能预算.md` 增加线程数、句柄数和大目录启动耗时预算。

- [x] 实现目录树按需枚举，只监控根目录和已展开目录，折叠或移除节点时释放对应子树监控。

## 风险与回滚

- 降低监控范围可能让未展开目录的变化不能立即显示；应在展开、窗口重新激活或用户刷新时补偿刷新。
- 共享线程池需要按 Tab 或请求序号丢弃过期结果，避免任务完成后访问已关闭 Tab。
- 不应只提高线程或句柄上限来掩盖问题；回滚时可恢复原监控策略，但必须保留基线测试。

- [x] 文件新增、删除、重命名可由展开目录 watcher 自动刷新；折叠期间变化在再次展开时重新读取。
